Resiliencia: qué pasa cuando algo externo falla
Qué hace el sistema cuando algo externo falla, se demora o se repite. La regla de fondo: al menos una entrega más
receptor idempotente equivale a una sola vez en efecto.
Qué pasa con cada dependencia externa
Dependencia
Si falla
Si se demora
Si se repite
Robot (SDK)
Se aborta la toma, se detiene la cámara y queda failed.
Nunca se reintenta el movimiento solo (reglas 1 y 7).
Tiempo límite en cada lectura de estado.
Pasado el tiempo, cuenta como fallo.
El ID de la toma y el candado lo rechazan (D16).
GoPro (USB)
Si no confirma que graba a tiempo, la toma no arranca
(regla 2).
Espera acotada. No se supone un tiempo
fijo.
Se lee el estado antes de repetir la orden de
grabar.
Descarga y render
Se conserva el original, se reintenta una vez y si no
queda failed.
Tiempo límite.
Repetir el render sobrescribe el mismo archivo.
Internet, R2 y la web
La cola reintenta con espera creciente y aleatoria, con
un tope de intentos. Persiste entre reinicios (C3).
Tiempo límite. El camino de la toma
nunca espera a la nube (regla 3).
El edge genera el id y la web hace upsert. El
archivo se sube con el mismo nombre (share_code
) y se sobrescribe.
Supabase
La web responde 503 y el edge reintenta. La página dice
"preparando tu video".
Igual que arriba.
Upsert por id.
Servicio de correo
(Resend)
Si el error es temporal, reintenta con espera. Si
rebota, queda bounced y el operador corrige.
Si pide esperar por un límite diario, el
envío pasa al día siguiente.
Cada envío es una fila en email_deliveries. El
reenvío es una orden explícita con su propio ID,
no un reintento ciego.
Limpieza diaria
Si no corre un día, el siguiente la alcanza, porque se
calcula por fecha.
Igual que arriba.
Correrla dos veces no hace nada extra.
¿Circuit breaker?
Sí, uno pequeño y solo en uploader/. El router 4G va y
viene: tras unos fallos seguidos la cola se pausa y
prueba con una sola petición cada cierto tiempo. Son
unas 20 líneas, sin librería.
En robot y cámara no se usa: se falla hacia el estado
seguro. En correo y web no hace falta con un solo
llamador y poco volumen.
A cuidar en un sistema de dos nodos
Una subida vieja no pisa un estado nuevo: el estado solo
avanza.
El correo se envía solo cuando la subida terminó (
video_upload_status = done).
Tras N intentos, un elemento imposible de subir pasa a
failed.
La tablet muestra subidas pendientes y fallidas.
Se propone guardar received_at con la hora del
servidor, por si el reloj del edge está mal.
Estado
Decidido: candado e idempotencia (D16), cola
persistente (C3) y camino local sin nube (regla 3).
Propuesto: el breaker en uploader/, la espera
creciente con aleatoriedad, el tope de intentos y la
visibilidad en la tablet.
Sin verificar: si el servicio de correo ofrece clave de
idempotencia. Si no, el estado en email_deliveries
evita el doble envío.
